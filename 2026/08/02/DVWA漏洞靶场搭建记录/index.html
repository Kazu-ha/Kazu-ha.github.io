DVWA漏洞靶场搭建记录

发表于2026-08-02|更新于2026-08-02|技术教程
|浏览量:

一、环境架构设计（为什么不用 Kali 直接搭？）

一开始我打算直接在 Kali 上部署 DVWA，但 Kali 是定制版，之前一次 apt update 直接把系统搞崩过，心有余悸，不敢再乱动。

方案：攻击机与靶机分离

角色 系统 职责 关键工具
攻击机 Kali Linux 发包、抓包、漏洞利用 Burp Suite + 火狐代理
靶机 Ubuntu 64位 独立承载 DVWA，承担”被攻击”角色 Apache + PHP + MySQL
网络 VMware NAT 双机互通 Kali 通过 192.168.170.128 访问 Ubuntu

环境参数速查

组件 版本/说明
靶机系统 Ubuntu 64位
Web 服务 Apache2
运行环境 PHP 8.1
数据库 MySQL 8.0
靶场项目 DVWA（最新版 Git 源码）
访问地址 http://192.168.170.128/dvwa

  • config 目录不可写

  • uploads 上传目录不可写

  • mod_rewrite 未开启

修复后刷新页面，核心报错全部消失。

5. 无效报错说明（新手极易焦虑）

剩余两个红色提示 无需修复，完全不影响漏洞学习：

  • reCAPTCHA key Missing：仅影响验证码暴力破解模块

  • Vendor files Not Installed：仅 API 功能依赖，Web 漏洞练习用不到

三、本次部署最大踩坑（核心难点）

坑点1：新版 DVWA + MySQL8.0 语法兼容报错

点击 Create / Reset Database 数据库初始化直接报错、页面崩溃。

报错根源：新版 DVWA 源码使用 ADD COLUMN IF NOT EXISTS 高版本语法，在部分 MySQL8.0 / MariaDB 环境存在兼容 BUG，初始化直接失败。

坑点2：Git 克隆目录嵌套 + 文件缺失

git clone 显示 100% 完成，但 ls includes/DBMS/MySQL.php 报错”无此文件”。
排查后发现源码多嵌套了一层 dvwa/dvwa/，导致后续所有相对路径都错了一位。

四、成功初始化 & 进入靶场

修复所有兼容与权限问题后，点击：

Create / Reset Database

页面自动跳转登录界面，部署完成！

默认账号密码：

  • 账号：admin

  • 密码：password

最终基础配置

进入 DVWA Security，确认安全等级为 Low，正式开启 Web 漏洞学习。

五、全局踩坑总结（可复用的建站经验）

  1. PHP 靶场优先看权限：uploads、config 目录权限是 90% 部署报错的元凶。

  2. 红色警告不全是问题：DVWA 检测页大量提示为附加功能，不影响核心漏洞实验。

  3. 新版本源码大概率兼容坑：新版 DVWA 对高版本数据库存在语法兼容 BUG，必须手动修复。

  4. 命令行严格区分服务端/客户端命令，拼写、多字母、空格都会直接报错。

  5. 本地靶场可放开权限：777 仅用于学习环境，生产环境绝对禁止授权最大权限。

六、后续学习计划

接下来将依次通关 DVWA 所有 Low 级别漏洞：

  • SQL 注入 & 布尔盲注、时间盲注

  • 文件上传漏洞绕过

  • 文件包含漏洞利用

  • XSS 跨站脚本攻击

  • 命令执行、弱口令爆破等

每通关一个漏洞，单独撰写原理 + 实操 + 复盘博客，建立个人漏洞知识库。
