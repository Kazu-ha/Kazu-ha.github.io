HTTP 协议-python request脚本

一、学习概述

完成 DVWA 漏洞靶场独立部署后，正式进入 Web 安全基础打底阶段。按照「底层网络 → 应用层协议 → 脚本实操 → 数据库基础」的路径系统学习，从 OSI 七层模型到 Python 发送 HTTP 请求，再到 MySQL 基础语法，完整打通 Web 请求全链路知识，为后续 SQL 注入、文件上传等漏洞学习筑牢基础。

二、网络基础核心知识点

2.1 OSI 七层模型

网络通信的分层标准，每一层各司其职，Web 安全绝大多数问题集中在应用层。

层级 名称 核心作用 安全相关
7 应用层 面向用户的网络服务（HTTP、FTP 等） 绝大多数 Web 漏洞发生层
6 表示层 数据格式转换、加密解密 HTTPS 加解密相关
5 会话层 建立、维持会话连接 会话管理、Cookie 机制基础
4 传输层 TCP/UDP 端口传输 端口扫描、SYN 洪水攻击
3 网络层 IP 寻址、路由转发 IP 伪造、DDoS 攻击
2 数据链路层 MAC 地址传输 ARP 欺骗、中间人攻击
1 物理层 物理介质传输 -

2.2 TCP/IP 协议特性

  • TCP：面向连接、可靠传输，通过三次握手建立连接、四次挥手断开连接，HTTP、FTP 等应用基于 TCP

  • UDP：无连接、不可靠、传输速度快，DNS、直播等场景使用

  • 安全视角：TCP 三次握手是 SYN 洪水攻击的原理；端口对应服务，是端口扫描的核心基础

2.3 DNS 解析流程

域名到 IP 地址的转换过程，完整链路：
本地缓存 → 递归 DNS 服务器 → 根域名服务器 → 顶级域服务器 → 权威 DNS 服务器 → 返回 IP 给客户端

  • 安全相关：DNS 劫持、域名欺骗、子域名枚举的底层原理

2.4 ARP 协议

  • 作用：局域网内将 IP 地址解析为 MAC 地址，是二层通信的基础

  • 安全相关：ARP 欺骗攻击，可实现局域网中间人劫持

2.5 HTTPS 基础概念

  • HTTP + SSL/TLS 加密层，解决 HTTP 明文传输的安全问题

  • 核心原理：非对称加密交换对称密钥，后续使用对称密钥加密传输数据

  • 安全相关：证书校验绕过、降级攻击、中间人攻击

三、MySQL 基础入门

SQL 注入是 Web 安全的头号漏洞，数据库基础是理解注入原理的前提。

3.1 库 / 表 / 字段关系

  • 数据库（Database）：数据的仓库，一个库可包含多张表

  • 表（Table）：同类数据的集合，由行和列组成

  • 字段（Field）：表的列，定义数据的类型和名称

  • 行（Row）：一条具体的数据记录

通俗类比：库 = Excel 文件，表 = 工作表，字段 = 列名，行 = 每行数据。

3.2 基础 SQL 语法

核心四大操作：增、删、改、查。

  1. 查询数据（SELECT）
  1. 插入数据（INSERT）
  1. 更新数据（UPDATE）
  1. 删除数据（DELETE）

3.3 UNION 联合查询

将多条 SELECT 语句的查询结果纵向合并返回，要求两边查询的字段数量必须一致。

重点：UNION 联合查询是 SQL 注入最常用的手法，后续漏洞实战会高频使用。

4.4 核心知识点总结

  1. requests.get() 发送 GET 请求，timeout 参数防止目标不通时程序卡死

  2. response.status_code 获取 HTTP 状态码，判断请求结果

  3. response.headers 获取响应头，可指纹识别后端 Web 服务版本

  4. 正则 re 匹配提取 HTML 内容，是简易爬虫和信息采集的基础

  5. argparse 实现命令行参数，是脚本工具化的必备写法

  6. 细分异常处理：连接失败、请求超时、通用异常分开捕获，便于定位问题

五、HTTP 协议核心梳理

HTTP 是 Web 通信的载体，所有漏洞 Payload 最终都通过 HTTP 数据包传递。

5.1 HTTP 请求方法

方法 用途 安全测试关注点
GET 获取服务器资源 参数在 URL 中易泄露，测试 URL 参数注入
POST 提交数据 参数在请求 Body，测试表单注入、越权提交
PUT 上传 / 更新资源 权限绕过、恶意文件上传漏洞
DELETE 删除资源 水平 / 垂直越权，未授权删除风险

5.2 常见状态码

状态码 含义 安全测试场景
200 OK 请求成功 页面 / 接口正常响应，可深入测试
301/302 重定向跳转 关注参数传递，测试 URL 跳转漏洞
403 Forbidden 权限不足 未授权拦截，尝试请求头 / 路径 / 参数绕过
404 Not Found 资源不存在 请求路径 / 文件不存在
500 服务器内部错误 高危信号，大概率存在 SQL 注入等漏洞

5.3 核心请求头

绝大多数请求头客户端可控，是安全测试的重要注入点。

Header 核心作用 安全意义
Host 指定目标服务器域名 Host 头攻击、虚拟主机越权
User-Agent 标识客户端身份 可伪造，绕过 WAF 检测
Cookie 携带用户会话凭证 身份认证核心，XSS 主要盗取目标
Referer 标记请求来源页面 防盗链 / CSRF 校验，可伪造绕过
X-Forwarded-For 传递客户端真实 IP 完全可伪造，绕过 IP 访问限制

5.4 Burp 抓包实战验证

通过 Burp 抓包真实网站验证：访问网站根路径 / 时，服务器先返回 302 Found，通过 Location 头指定跳转目标，浏览器自动发起二次请求后才返回 200 OK 的真实页面，与理论完全对应。

六、今日踩坑与全局总结

6.1 踩坑记录

  1. requests 请求不加 timeout，目标不存活时程序会长时间卡死

  2. 正则匹配 title 不加 re.IGNORECASE，遇到大写 <TITLE> 标签会匹配失败

  3. SQL 语句中字符串值必须加引号，漏写会直接触发语法报错

6.2 全局总结

  1. 网络分层是理解所有网络通信的基础，Web 漏洞基本都集中在应用层

  2. HTTP 是 Web 交互的载体，所有攻击载荷最终都要封装进 HTTP 数据包

  3. Python requests 是安全自动化的基石，后续爆破、注入、扫描脚本都会基于它扩展

  4. MySQL 语法是 SQL 注入的前提，不懂 SQL 就无法理解注入漏洞的本质
