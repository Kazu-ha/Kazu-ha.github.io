HTTP 协议基础与 Burp 抓包练习

发表于2026-08-08|更新于2026-08-09|技术教程
|浏览量:

一、前言

正式进入 Web 安全学习阶段。而 HTTP 协议是所有 Web 漏洞的基础载体，不管是 SQL 注入、XSS 还是文件上传，最终都要通过 HTTP 数据包传递 Payload。
本篇系统整理 HTTP 核心知识点，从请求方法、状态码、核心 Header三大基础模块，再到 Burp Suite 抓包官网实战，把理论和实操对应起来。

二、HTTP 请求方法

HTTP 协议定义了多种请求方法，对应不同的操作语义。在安全测试中，不同方法的攻击面和测试重点完全不同：

方法 用途 安全测试关注点
GET 获取服务器资源 参数拼接在 URL 中，易泄露敏感信息；重点测试 URL 参数注入
POST 向服务器提交数据 参数放在请求 Body 中；重点测试表单注入、越权提交
PUT 上传 / 更新服务器资源 测试权限绕过、恶意文件上传漏洞
DELETE 删除服务器资源 测试水平 / 垂直越权，未授权删除风险

实操提示：Web 安全测试不能只看业务使用的方法，可尝试篡改请求方法（POST 改 GET、PUT/DELETE），验证服务端是否做了严格的方法校验，很多越权漏洞由此产生。

三、HTTP 状态码

状态码是服务器对请求的响应结果标识，不同状态码对应不同的安全测试信号，是判断漏洞存在的重要依据。

状态码 官方含义 安全测试场景
200 OK 请求成功 接口 / 页面正常响应，可继续深入测试
301/302 重定向跳转 关注跳转时参数是否跟随传递，测试 URL 跳转漏洞
400 Bad Request 请求格式错误 数据包构造有误，需检查参数格式
403 Forbidden 权限不足 未授权访问拦截，可尝试请求头、路径、参数方式绕过
404 Not Found 资源不存在 请求路径 / 文件不存在
500 Internal Server Error 服务器内部错误 高危信号！大概率存在 SQL 注入等漏洞，通常伴随报错信息泄露
502/503 网关错误 / 服务不可用 后端服务宕机或过载，可测试拒绝服务相关场景

核心经验：遇到 500 优先测试注入类漏洞；遇到 403 不要直接放弃，优先尝试各种绕过手段。

四、核心 HTTP 请求头

请求头是客户端向服务器传递附加信息的载体，绝大多数请求头都可被客户端伪造，是安全测试中重要的可控变量。

Header 核心作用 安全意义
Host 指定目标服务器域名 可测试 Host 头攻击、虚拟主机越权
User-Agent 标识客户端浏览器身份 可任意伪造；部分 WAF 基于 UA 检测，可通过伪造 UA 绕过
Content-Type 声明请求体数据格式 文件上传漏洞绕过关键，修改 MIME 类型可欺骗后端校验
Referer 标记请求来源页面 用于防盗链、CSRF 防护校验，可伪造绕过
Cookie 携带用户会话凭证 身份认证核心，也是 XSS 漏洞的主要盗取目标
X-Forwarded-For 传递客户端真实 IP 完全可伪造，用于绕过 IP 黑名单、IP 访问限制

记忆要点：Cookie、Referer、X-Forwarded-For、User-Agent 均为客户端完全可控，凡是基于这些字段做的安全校验，都存在被绕过的可能。

五、Burp Suite 抓包练习

以中国民航大学官网 www.cauc.edu.cn 为目标，进行基础抓包分析，把上面的理论对应到真实数据包中。

1. 302 重定向流程分析

直接访问网站根路径 /，服务器并不会直接返回页面，而是返回 302 重定向：

完整访问链路：

  1. 浏览器发起 GET / 请求

  2. 服务器返回 302 Found，通过 Location 头指定跳转目标 /zhv5/

  3. 浏览器自动发起第二次请求 GET /zhv5/

  4. 服务器返回 200 OK，返回真实网页内容

安全考点：如果 Location 头的值可被用户参数控制，就会形成开放重定向漏洞，可用于钓鱼攻击。

2. 站点地图与响应安全头

Burp 的 Site map 会自动梳理网站的目录结构，可以直观看到网站的所有路径分支，如 jwc、system、xxgk2018 等功能模块。

在 200 响应包中，可以看到服务器返回的安全响应头：

响应头 安全作用
X-Frame-Options: SAMEORIGIN 防止点击劫持，仅允许本站域名嵌入 iframe
X-XSS-Protection: 1; mode=block 开启浏览器内置 XSS 过滤器，检测到 XSS 直接拦截页面
X-Content-Type-Options: nosniff 禁止浏览器自动嗅探文件 MIME 类型，防御 MIME 类型混淆攻击
Referrer-Policy 控制 Referer 信息的传递范围，减少信息泄露
Content-Security-Policy (CSP) 内容安全策略，严格限制页面可加载的外部资源，是防御 XSS 的强力手段

同时响应头中 Server: WebServer 也会泄露服务端指纹，攻击者可针对对应版本寻找已知漏洞。

六、全局知识点总结

  1. 方法决定操作：GET 查、POST 增、PUT 改、DELETE 删，不同方法对应不同漏洞测试方向。

  2. 状态码是信号：200 正常测、302 看跳转、403 试绕过、500 找注入。

  3. 请求头大多可控：Cookie、UA、Referer、XFF 都能伪造，基于它们的校验都不可靠。

  4. 响应头看防护：通过返回的安全头，可以判断网站的基础安全防护强度。

  5. 重定向是常见流程：访问根目录 302 跳转到真实首页是绝大多数网站的常规操作，抓包时注意二次请求。
