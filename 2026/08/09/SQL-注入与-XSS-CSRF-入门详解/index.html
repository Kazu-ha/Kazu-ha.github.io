SQL 注入与 XSS/CSRF 入门详解

发表于2026-08-09|更新于2026-08-09|技术教程
|浏览量:

一、学习概述

集中攻克 Web 安全三大高频漏洞：SQL 注入、XSS 跨站脚本、CSRF 跨站请求伪造，同时补充命令注入漏洞原理，全程以 DVWA 靶场为实操载体，从底层原理到手工注入复现，再到防护绕过思路，完整建立「原理 - 利用 - 修复」的漏洞思维框架。

⚠️ 安全声明：所有漏洞实操均在本地自建 DVWA 靶场中完成，禁止对未授权网站进行漏洞测试。漏洞平台仅做规则学习，严格遵守「只读不挖」原则。

二、SQL 注入核心原理与手工注入

2.1 注入点类型

SQL 注入的本质是用户可控参数拼接到 SQL 语句中，恶意篡改原有 SQL 逻辑，根据参数类型分为两大类：

类型 特征 判断方法
数字型 参数为整数，无引号包裹 输入 and 1=1 正常，and 1=2 报错 / 页面异常
字符型 参数为字符串，被单 / 双引号包裹 输入单引号触发语法报错，输入 ' and '1'='1 恢复正常

核心判断依据：单引号是否触发数据库语法报错，报错即说明参数可能直接拼接进 SQL 语句。

2.2 DVWA Medium 等级手工注入流程

Medium 等级对单引号做了转义，但仍为数字型注入，可直接通过数值参数构造 Payload，完整手工注入步骤：

  1. 判断注入点与闭合方式
    输入 1 and 1=1 页面正常，1 and 1=2 数据消失，确认数字型注入。

  2. order by 猜解字段数

确认查询结果为 2 个字段。

  1. union 联合查询定位回显位

确认第 2 位是页面回显点。

  1. 查询数据库名与版本
  1. 查询所有表名
  1. 查询字段名
  1. 脱库获取账号密码

2.3 WAF 基础概念

WAF（Web 应用防火墙）是部署在 Web 前端的安全防护设备，通过特征匹配拦截 SQL 注入、XSS 等攻击 Payload。

  • 常见检测规则：关键字拦截（select、union、and）、特殊符号拦截、长度限制

  • 基础绕过思路：大小写绕过、双写绕过、编码绕过、注释符绕过、等价函数替换

三、XSS 跨站脚本攻击

3.1 XSS 三类核心原理

XSS 本质是恶意 JavaScript 代码被插入到网页中，在用户浏览器端执行，根据触发方式分为三类：

类型 原理 触发场景 危害等级
反射型 Payload 拼接在 URL 中，服务器反射回页面 搜索框、错误页、参数回显 中，需诱导用户点击链接
存储型 Payload 存入数据库，访问页面自动触发 留言板、评论区、个人资料 高，无需诱导，访问即中招
DOM 型 前端 JS 直接读取 URL 参数写入页面，不经过后端 前端路由、锚点、本地渲染 中，纯前端漏洞

3.2 DVWA XSS 全等级防护对比

等级 防护方式 绕过思路
Low 无任何过滤 直接 <script>alert(1)</script>
Medium 过滤 <script> 标签 双写绕过 <scr<script>ipt> 或使用 img 标签
High 正则过滤所有 script 标签 使用事件触发 <img src=x onerror=alert(1)>
Impossible 实体化转义输出 无法利用，标准修复方案

3.3 XSS 核心危害

  • 窃取用户 Cookie，直接登录他人账号

  • 伪造页面操作，诱导用户转账 / 改密码

  • 弹窗钓鱼、挂马、挖矿

  • 结合浏览器漏洞获取主机权限

四、CSRF 漏洞原理与利用

4.1 漏洞本质

CSRF（跨站请求伪造）：攻击者诱导用户在已登录状态下，访问第三方恶意页面，利用用户的 Cookie 身份，悄无声息地向目标网站发送请求，执行非用户本意的操作。

核心三要素：

  1. 用户已登录目标网站，浏览器保存有效 Cookie

  2. 目标网站关键操作仅靠 Cookie 验证身份

  3. 用户访问攻击者构造的恶意页面

4.2 CSRF 与 XSS 的区别

维度 XSS CSRF
执行位置 目标网站页面内 第三方恶意站点
核心 注入 JS 代码执行 伪造用户身份发请求
交互 需要注入点 需要用户点击访问
危害 窃取 Cookie、控制页面 改密码、转账、发消息

4.3 标准修复方案

  • 添加 CSRF Token 令牌，每次请求携带随机校验值

  • 关键操作增加二次验证（短信、密码、验证码）

  • 校验 Referer 请求来源

  • SameSite Cookie 属性限制跨站携带

五、命令注入漏洞

5.1 底层原理

当 Web 应用调用系统命令执行功能，且命令参数由用户可控时，攻击者可通过管道符、连接符拼接额外命令，实现任意系统命令执行。

常用命令连接符：

  • ;：顺序执行多条命令

  • &&：前一条成功才执行后一条

  • ||：前一条失败才执行后一条

  • |：管道符，前一条输出作为后一条输入

六、全局踩坑与经验总结

6.1 踩坑记录

  1. SQL 注入时忘记注释符闭合后面的引号，反复触发语法报错

  2. Medium 等级 XSS 直接用 script 标签失效，忽略了标签过滤，改用事件标签成功

  3. 命令注入只记得 &&，被过滤后卡住，实际还有 | || 多种连接符可选

  4. 手工注入字段数猜解时从 1 开始逐个试效率低，可二分法快速定位

6.2 核心方法论

  1. 所有漏洞本质都是「输入可控 + 过滤不严」，找到可控参数是第一步

  2. 先判断类型，再构造 Payload，不要上来就盲目试 Payload

  3. 防护等级越高，绕过思路越要发散，等价函数、特殊编码、标签替换都是常用思路

  4. 漏洞学习要形成闭环：原理 → 复现 → 绕过 → 修复，四个环节缺一不可
